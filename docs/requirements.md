## 1. システム概要

### 1.1 背景と目的

卒業研究（テーマ：鎌倉市のコミュニティ通貨「まちのコイン鎌倉（クルッポ）」の利用促進・阻害要因の解明と改善策の設計）において、文献の探索・管理・執筆を一貫して支援するローカルツールを構築する。

従来の文献管理では以下の課題がある：

- 複数の学術データベースを個別に検索する手間
- 論文のPDF管理と要約が散逸する
- AIによる要約でハルシネーション（事実に基づかない記述）が発生するリスク
- 論文の主張と根拠文献の対応関係が不明確になる

litkit はこれらの課題を解決し、**「探す → 取り込む → 要約する → 蓄える → 引ける → 書く」** の一連の研究ワークフローを一本化する。

### 1.2 利用者

- 本システムの利用者は卒業研究を行う学生1名（個人利用）
- 4年次の1年間、日常的に使用する研究支援ツールとして運用

### 1.3 利用環境

- OS: Windows 11
- ランタイム: Python 3.12以上、Node.js 18以上
- パッケージ管理: uv（Python）、npm（JavaScript）
- バージョン管理: Git + GitHub（privateリポジトリ）

## 2. 機能要件

### 2.1 文献検索（FR-01）

| 項目 | 内容 |
|------|------|
| 概要 | 複数の学術データベースを横断検索し、結果をL1要約付きで一覧表示する |
| 入力 | 検索クエリ（日本語 or 英語） |
| 出力 | 統合された検索結果リスト（タイトル、著者、年、ソース、関連度、L1要約） |
| 対応ソース | CiNii Research、J-STAGE、CrossRef、OpenAlex、Semantic Scholar、arXiv、国立国会図書館（NDL） |

**詳細仕様：**

- 日本語クエリの場合、CLAUDE.md の研究キーワードから自動で英語クエリも生成し、並行検索する
- 各ソースへの検索は非同期で並行実行する（`asyncio.gather`）
- DOI に基づく重複排除を行う
- 研究テーマとの関連度を自動判定する（high / mid / low）
  - CLAUDE.md のキーワードリストとのマッチ数で判定（3以上: high、1以上: mid、0: low）

### 2.2 文献プレビュー（FR-02）

| 項目 | 内容 |
|------|------|
| 概要 | 検索結果の詳細情報を表示し、取り込むかどうかの判断材料を提供する |
| 入力 | 検索結果番号 |
| 出力 | L2判断用要約（300〜500字）、書誌情報、アクセス可能性 |

### 2.3 文献取込（FR-03）

| 項目 | 内容 |
|------|------|
| 概要 | 検索結果またはDOI/URLから文献カードを生成し、ライブラリに追加する |
| 入力 | 検索結果番号、DOI、またはURL |
| 出力 | Markdownファイル（`literature/cards/{id}.md`） |

**文献カードの構造：**

```yaml
# YAML frontmatter
id: string          # 一意識別子
title: string       # 論文タイトル
authors: [string]   # 著者リスト
year: int | null    # 出版年
venue: string | null # 掲載誌
doi: string | null  # DOI
url: string | null  # URL
source: enum        # 取得元（cinii/jstage/crossref/openalex/semantic_scholar/arxiv/ndl/manual/web）
lang: enum          # 言語（ja/en）
pdf: string | null  # PDFファイルパス
status: enum        # 状態（unread/reading/read）
depth: enum         # 深度（abstract_only/full_text）
rating: int | null  # 評価（1-5）
tags: [string]      # タグ
relevance: enum     # 関連度（high/mid/low）
l1: string | null   # L1一行要約
added: date         # 追加日
updated: date       # 更新日
```

**カード本文セクション：**

- L1一行要約
- L2判断用要約（300〜500字）
- L3精読要約（本文取得時のみ）
- 自研究との関係
- メモ・疑問

### 2.4 3層要約システム（FR-04）

| 層 | 情報源 | 分量 | 目的 | 生成条件 |
|----|--------|------|------|----------|
| L1 | 書誌＋アブストラクト | 1〜2行 | 一覧で候補を絞る | 検索結果取得時 |
| L2 | アブストラクト＋取得範囲 | 300〜500字 | 読む価値があるか判断 | プレビュー/取込時 |
| L3 | 本文PDF全文 | 制限なし | 内容把握・引用 | **PDF全文取得時のみ** |

**制約事項：**

- `depth: abstract_only` のカードに対してL3精読要約を生成してはならない
- L3は本文PDFを取得・テキスト抽出した場合にのみ生成可能

### 2.5 PDF管理（FR-05）

| 項目 | 内容 |
|------|------|
| 概要 | PDFの取得・保管・テキスト抽出を管理する |
| ダウンロード | OAの場合、URLからPDFを `literature/pdf/` に保存 |
| テキスト抽出 | PyMuPDFによるPDF全文テキスト抽出 |
| inbox処理 | `literature/inbox/` に手動配置したPDFを取り込む（DOI自動検出） |

**セキュリティ制約：**

- `literature/pdf/` と `literature/inbox/` は `.gitignore` で除外し、Git管理下に置かない（著作権上の理由）

### 2.6 全文検索（FR-06）

| 項目 | 内容 |
|------|------|
| 概要 | 蓄積した文献カードの全文検索 |
| 実装 | SQLite FTS5 |
| 格納場所 | `data/litkit.db`（再生成可能なキャッシュとして扱う） |
| 機能 | カードのタイトル・著者・L1・タグ・本文を対象とした全文検索 |

### 2.7 蓄積文献への質問（FR-07）

| 項目 | 内容 |
|------|------|
| 概要 | 取り込んだ文献の内容に基づいて質問に回答する |
| 入力 | 自然言語の質問 |
| 出力 | 根拠カードIDを明示した回答 |

**制約事項：**

- カードに書かれていない情報を論文の内容として記述しない
- `depth: abstract_only` の根拠には「アブストのみに基づく」と但し書きを付す

### 2.8 主張・根拠管理（FR-08）

| 項目 | 内容 |
|------|------|
| 概要 | 論文の主張と根拠文献の対応をMarkdownテーブルで管理する |
| 格納 | `thesis/claims.md` |
| 検査 | 根拠なしの主張を検出、無効なカード参照を検出 |
| 指標 | カバー率（根拠付き主張の割合）をダッシュボードに表示 |

### 2.9 整合性チェック（FR-09）

| 項目 | 内容 |
|------|------|
| 概要 | 論文全体の品質を自動チェックする |
| チェック項目 | 1. 根拠なし主張の検出 |
| | 2. 無効なカード参照の検出 |
| | 3. 用語一貫性（`notes/glossary.md` との照合） |
| | 4. 図番号の連番チェック |

### 2.10 引用出力（FR-10）

| 項目 | 内容 |
|------|------|
| 概要 | 蓄積文献から参考文献リストを生成する |
| 出力形式 | BibTeX、日本語慣例形式、APA形式 |
| オプション | `--used-only` で主張に紐づく文献のみ出力 |

### 2.11 週次レポート（FR-11）

| 項目 | 内容 |
|------|------|
| 概要 | 1週間の研究活動をまとめたレポートを自動生成する |
| 内容 | 追加文献数、精読文献数、主張カバー率の推移、日次ログ |

## 3. 非機能要件

### 3.1 データ管理方針（NFR-01）

| 項目 | 方針 |
|------|------|
| 単一情報源 | Markdown + YAML frontmatter が正（Single Source of Truth） |
| SQLite | 再生成可能なキャッシュ。紛失しても `reindex` で復旧できる |
| PDF | ローカル保存のみ。リポジトリに含めない |
| 設定 | APIキーは `.env` で管理。リポジトリに含めない |

### 3.2 ハルシネーション防止（NFR-02）

| ルール | 内容 |
|--------|------|
| 根拠の明示 | 文献に基づく記述には必ず根拠カードIDを付す |
| 不在の明示 | 根拠が見つからない場合は「蓄積文献中に該当なし」と明示する |
| 書誌の厳格性 | 著者名・年・掲載誌・DOIを推測で補完しない。取得不可なら null |
| L3の条件 | abstract_only のカードからL3を生成しない |
| 事実と考察の分離 | カード内の事実セクションと考察セクションを構造的に分離する |

### 3.3 セキュリティ（NFR-03）

| 項目 | 対策 |
|------|------|
| ネットワーク | APIサーバーは `127.0.0.1` でバインド（`0.0.0.0` は使用しない） |
| 著作権 | PDFをGitリポジトリに含めない |
| 秘密情報 | `.env`、APIキーをリポジトリに含めない |
| リポジトリ | GitHub上はprivateリポジトリとする |

### 3.4 テーマ依存語彙の管理（NFR-04）

- 研究テーマ固有のキーワード（日本語・英語）は `CLAUDE.md` の「研究の文脈」セクションに一元管理する
- ソースコードにキーワードをハードコードしない
- 関連度判定などのロジックは `CLAUDE.md` からキーワードを動的に読み込む

## 6. 外部ソースアダプタ仕様

| ソース | API形式 | 認証 | 備考 |
|--------|---------|------|------|
| CiNii Research | OpenSearch (JSON) | 不要 | 日本語論文の主要ソース |
| J-STAGE | REST (XML/Atom) | 不要 | 日本語学術雑誌 |
| CrossRef | REST (JSON) | 不要 | DOI解決、HTMLアブスト解析 |
| OpenAlex | REST (JSON) | メール推奨 | 転置インデックスからアブスト復元 |
| Semantic Scholar | Graph API (JSON) | APIキー推奨 | 引用ネットワーク |
| arXiv | Atom/XML | 不要 | プレプリント |
| NDL（国立国会図書館） | OpenSearch (JSON) | 不要 | 日本の出版物全般 |

## 7. 制約事項・前提条件

### 7.1 制約事項

1. 個人利用を前提とする（マルチユーザー非対応）
2. ローカル実行のみ（クラウドデプロイ非対応）
3. インターネット接続が必要（外部API検索時）
4. PDF全文はローカル保存のみ（リポジトリ外）
5. APIサーバーは localhost のみでバインド

### 7.2 前提条件

1. Python 3.12以上がインストールされていること
2. Node.js 18以上がインストールされていること
3. uv パッケージマネージャがインストールされていること
4. Git がインストールされていること

## 8. 将来の拡張候補

以下は現バージョンでは未実装だが、将来の拡張として想定される機能：

1. **MCP Server化** — Claude DesktopからIndex検索を直接呼び出せるようにする
2. **引用ネットワーク可視化** — 文献間の引用関係をグラフで表示
3. **自動PDF取得** — OA論文のPDFを自動ダウンロード
4. **多言語対応** — 中国語・韓国語の文献ソース追加
5. **エクスポート機能** — 文献カードをEndNote/Zotero形式で出力

## 付録A: Git管理対象

| パス | Git管理 | 理由 |
|------|---------|------|
| `src/litkit/` | 対象 | ソースコード |
| `web/src/` | 対象 | フロントエンドソース |
| `literature/cards/` | 対象 | 文献カード（研究成果物） |
| `thesis/` | 対象 | 卒論原稿 |
| `notes/` | 対象 | 研究ノート |
| `CLAUDE.md` | 対象 | 運用ルール |

| `literature/inbox/` | **除外** | 一時ファイル |
| `data/` | **除外** | 再生成可能なキャッシュ |
| `.env` | **除外** | APIキー等の秘密情報 |
| `web/node_modules/` | **除外** | 依存パッケージ |
| `web/dist/` | **除外** | ビルド成果物 |
